## บทบาท (บังคับด้วย gateway `src/lib/annual-checkup-db.ts` + trigger ในฐานข้อมูล)
- **เจ้าหน้าที่กรอกผล** `health_result_recorder`: กรอก/นำเข้า/แนบไฟล์/ส่งให้แพทย์ — อนุมัติและเปิดผลไม่ได้
- **แพทย์ผู้อนุมัติ** `health_result_approver` (แพทย์ + เลขใบอนุญาต + ปลดล็อกด้วยเลขใบอนุญาต): เขียนสรุป ส่งกลับ ตรวจสอบ เปิดผล
- **เจ้าของระบบ**: ให้/ถอนสิทธิ์ที่ `/admin/persona/annual-checkup/permissions` (ต้องใส่เหตุผล เก็บประวัติ) ตั้งค่าที่ `/admin/persona/annual-checkup/settings`
- สิทธิ์ใช้ได้เฉพาะคนที่อยู่สาขา AT HOME CLINIC ทุกครั้งที่เขียน; ถอนสิทธิ์/ย้ายสาขา = หยุดทันที
- **ฝ่ายบุคคล/แอดมิน**: เห็นจำนวนคนต่อขั้นตอนเสมอ; เห็นชื่อ+ภาพรวมของคนที่ติดตามเฉพาะที่พนักงานยินยอม (`followup`); เปิดเล่มผลได้เฉพาะคนที่ยินยอม `values` (บันทึกในรายการ "ใครเปิดดูข้อมูลฉัน" ของพนักงาน)
- **พนักงาน**: เห็นเฉพาะของตัวเองที่เปิดผลแล้ว (PDPA + PIN + หน้าต่าง 15 นาที เหมือนเดิม)
- **คนไม่มีบัญชี**: ลิงก์สุ่ม (เก็บเฉพาะ hash) หมดอายุได้ + ยืนยันวันเกิด + ผิด 5 ครั้งล็อก 30 นาที
- ผลเอชไอวีไม่อยู่ในเล่ม (ซ่อนจากรายงาน); สารเสพติดเห็นเฉพาะแพทย์/ทีมคลินิกและเจ้าตัว

## ตารางใหม่ (additive, สร้างตอนระบบเริ่ม, ย้อนกลับ: `docs/migrations/health-report-pr1-rollback.sql`)

## สิ่งที่ยังต้องให้คน/แพทย์ยืนยัน
- ค่าอ้างอิงที่ติด ⚠ (ดู `docs/health-report-reference-ranges.md` และหน้าตั้งค่า)
- ข้อความคำอธิบายทั้งหมด (พิมพ์จากภาพต้นแบบ) และที่อยู่บริษัทที่ปกหลัง (`contacts.ts`)
- ไฟล์ Excel ของแล็บยังไม่เคยเห็นของจริง: คอลัมน์ที่ไม่รู้จักจะถูกแจ้งในหน้าตัวอย่าง ไม่ถูกเดา
- ลิงก์ปรึกษาแพทย์ (ตั้งในหน้าตั้งค่า) ผลปีเก่า (2567/2568) ต้องนำเข้าถ้าต้องการให้ขึ้น


## ผู้รับการตรวจภายนอก (external examinees)

คนของบริษัทลูกค้าที่ไม่มีบัญชีและไม่อยู่ใน PERSONA — เป็นแถวใน `annual_checkup_externals` (มีอยู่เดิม) ไม่ใช่ `users`.
เสริมแบบ additive เท่านั้น (migration ใหม่ ไม่แก้อันเก่า; rollback อยู่ใน `docs/migrations/health-report-pr1-rollback.sql`).

**โครงสร้าง**
- `annual_checkup_external_details` (1 แถวต่อคน): คำนำหน้า/ชื่อ/นามสกุล, เบอร์, อีเมล, **เลขบัตร 4 ตัวท้ายเท่านั้น**, รหัสพนักงานที่บริษัท,
  `consent_pdpa_at`, `consent_release_to_sponsor` (ค่าเริ่มต้น 0). อ่าน/เขียนผ่าน gateway (`annual-checkup-db.ts`) เท่านั้น — อยู่ในรายการ `check:risks`
- `annual_checkup_payer_prefixes`: ตัวย่อบริษัท → รหัสตรวจ (`TSR`, `POA`); รหัสคือ `<ตัวย่อ><ปี 2 หลัก>-<เลข 4 หลัก>` เช่น `TSR69-0004`
  (ถ้าเลขซ้ำในรอบ จะข้ามไปเลขถัดไปที่ว่าง); หลอดแล็บเติม `-G` (น้ำตาล) หรือ `-R` (เคมีอื่น)
- ไม่มี RLS (ระบบเป็น SQLite) — การแยกสิทธิ์ทำที่ gateway + trigger + audit log; ทดสอบใน `test-health-external*.ts`

**การนำเข้าไฟล์แผน (Excel)** — หน้า `/admin/persona/annual-checkup` → นำเข้า
- ก = จับคู่พนักงานได้ · ข = จับคู่ไม่ได้ + ผู้จ่ายเป็นบริษัทภายนอก (**ติ๊กต่อแถวหรือต่อบริษัท ไม่สร้างเอง**) · ค = จับคู่ไม่ได้ + ผู้จ่ายเป็นบริษัทในกลุ่ม (ข้ามพร้อมเหตุผล)
- นำเข้าซ้ำได้: หาคนเดิมด้วย บริษัท + ชื่อ + นามสกุล (+ วันเกิดถ้ามีคอลัมน์ "วันเกิด") ไม่สร้างซ้ำ ไม่แตะผลที่ลงแล้ว
- ปุ่ม "เพิ่มผู้รับการตรวจภายนอก" ที่หน้ารอบ (staff/health) สำหรับคนที่ไม่อยู่ในไฟล์

**ผลแล็บ** — หน้า "นำเข้าผลจากไฟล์แล็บ" รับ .xlsx หรือไฟล์ ReportBackup (.txt/.csv)
- `Sample ID=<รหัสตรวจ>-<G|R>` → คน; `GLU→FBS, CHOL→CHOL, TRI→TG, BUN→BUN, CRE→CREAT, URIC→URIC, AST→AST, ALT→ALT`;
  ค่าจากหลอดผิดชนิด / ค่าซ้ำไม่ตรงกัน / รหัสที่ไม่รู้จัก ไม่ถูกนำเข้า (รายงานแยก); ต้องดูตัวอย่างก่อน; ค่าเดิมที่ต่างจะไม่ถูกเขียนทับถ้าไม่ติ๊ก
- **สมมติฐาน:** รูปแบบ ReportBackup เขียนแบบยืดหยุ่นโดยยังไม่เคยเห็นไฟล์จริง — ถ้าอ่านไม่ได้ระบบแจ้งและไม่เดา

**เปิดผล / ลิงก์ / บริษัท**
- เปิดผลด้วยกลไกเดิม (`releaseCompany` ครอบคลุมคนภายนอก; ต้องปลดล็อกด้วยเลขใบอนุญาต)
- ลิงก์ส่วนตัว `/health/r/<token>`: token สุ่มยาว เก็บเฉพาะ hash, เปิดด้วยวันเกิดหรือเลขบัตร 4 ตัวท้าย, ล็อก 30 นาทีเมื่อผิด 5 ครั้ง, อายุปกติ 30 วัน,
  ยกเลิก/ออกใหม่ได้ (ออกใหม่ยกเลิกลิงก์เดิมทั้งหมด), ทุกการเปิดอยู่ใน audit (`link.view`)
- สรุปสำหรับบริษัท `/staff/health/annual-checkup/<รอบ>/sponsor/<บริษัท>`: จำนวนคน/ตรวจครบ/ออกผล + ความพร้อม (เหมาะสม / เหมาะสมแต่ควรติดตาม / ควรพบแพทย์ จากสรุปแพทย์ที่ออกผลแล้ว)
  **ไม่มีค่าแล็บรายคน** เว้นแต่คนนั้นยินยอม (`consent_release_to_sponsor`) และผลออกแล้ว
- ไม่มีการส่งค่าผลตรวจทาง LINE หรือการแจ้งเตือนใดๆ สำหรับคนภายนอก
