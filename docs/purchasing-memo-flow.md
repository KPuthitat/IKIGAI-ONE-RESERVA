# ระบบเบิกจ่าย: Memo → ลงลายมือชื่อ → PR → PO (เจ้าของระบบ 2569-11-26)

## ภาพรวมที่เจ้าของระบบกำหนด
- ทุกการซื้อต้องผ่าน PR/PO ในระบบก่อน; PR ทั่วไป (บัญชี SCB) อนุมัติโดย **ผู้บริหาร 2 คน หรือผู้บริหารสูงสุด 1 คน**
- KBANK (ฝ่ายจัดซื้อ): วางแผนขอเบิกรายสัปดาห์จาก SCB มารอไว้ แล้วผู้บริหารฝั่งนั้นเบิก ผ่าน PR/PO เช่นกัน อนุมัติโดย **ผู้บริหาร 1 คน**
- ทุกอย่างเริ่มจาก **Memo**: เลือกผู้เกี่ยวข้อง → แจ้งเตือน → แต่ละคนลงลายมือชื่อ (ลายเซ็นดิจิตอล) → ครบทุกคน = Memo อนุมัติ → ผู้ขอซื้อกดเปิด PR (ดึงข้อมูลจาก Memo) → ผู้บริหารอนุมัติ PR → เปิด PO → ซื้อได้
- บัญชี: SCB 3 (ออม — ตัดออมทุกเดือน / เงินหมุนเวียน / Payroll + เตรียมจ่ายภาษี), KBANK 1, SME D BANK 1

## รอบที่ 1 (ทำแล้ว) — Memo + ลายเซ็นดิจิตอล + แจ้งเตือน + เปิด PR จาก Memo
- หน้า `/admin/memos` (เมนู "เบิกจ่าย" · badge = Memo ที่รอฉันลงนาม) · ตาราง `memos`, `memo_items`, `memo_signers`, `memo_events`, `user_signatures`; คอลัมน์ `purchase_requests.memo_id`
- ผู้เขียน Memo = แอดมินสาขา/ผู้บริหาร (คนที่เปิด PR ได้อยู่แล้ว); ผู้ลงนาม = แอดมิน/ผู้บริหารที่ทำงานอยู่ (ไม่ใช่ผู้เขียน)
- ลงนามต้องมีลายเซ็นที่วาดไว้ในโปรไฟล์ + PIN 4 หลัก (PIN เดียวกับหน้าลงเวลา); ทุกการลงนามเก็บสำเนาลายเซ็นไว้กับ Memo (แก้ลายเซ็นภายหลังไม่กระทบ Memo ที่ลงไปแล้ว)
- ผู้ลงนามคนใดไม่เห็นชอบ (ต้องมีเหตุผล) → Memo ตกทันที ผู้เขียนแก้ไขแล้วส่งใหม่ (ลายเซ็นทั้งหมดถูกล้าง)
- ลงนามครบ → ผู้เขียนกด "เปิด PR จาก Memo": สร้าง PR ใหม่จากรายการ/ผู้จำหน่าย/VAT/เหตุผลของ Memo แล้วส่งขออนุมัติเลย (ผูก `memo_id`) และแจ้งผู้บริหารที่อนุมัติ PR
- แจ้งเตือนทาง LINE (ผู้ลงนาม / ผู้เขียน / ผู้อนุมัติ PR) + รายการ "รอฉันลงนาม" และ badge ในเมนู · พิมพ์ Memo พร้อมลายเซ็นได้

## รอบที่ 2 (ทำแล้ว) — อำนาจอนุมัติตามบัญชีและยอด + ขอเบิกเงินรายสัปดาห์
- **อำนาจอนุมัติ PR** (`/admin/accounta/authority` เจ้าของระบบเท่านั้น): แบ่งขั้นตามยอด PR แยกบัญชี (ค่าเริ่มต้นทั้งบริษัทเมื่อไม่ได้ตั้งเอง; ถ้าไม่ตั้งเลย = ผู้บริหาร 2 คน หรือผู้บริหารสูงสุด 1 คน) กฎมี 3 แบบ: ผู้บริหาร 1 คน / ผู้บริหาร 2 คน หรือสูงสุด 1 คน / ผู้บริหารสูงสุดเท่านั้น; ตั้ง "ผู้อนุมัติประจำบัญชี" (ใช้กับขั้น 1 คน เช่น ฝั่งจัดซื้อ KBANK) และติ๊ก "ผู้บริหารสูงสุด" (ถ้ายังไม่มีใครถูกติ๊ก เจ้าของระบบทำแทนชั่วคราว)
- PR เลือก "จ่ายจากบัญชี" (สืบทอดจาก Memo); การอนุมัติหลายคนเก็บใน `pr_approvals` แสดงความคืบหน้าและผู้อนุมัติที่เหลือในหน้า PR; ส่งใหม่/เปิดซ้ำ = ล้างการอนุมัติ
- **Memo ขอเบิกเงิน** (`memo_kind='funding'`): โอนจากบัญชีต้นทาง → ปลายทาง, ยอด, สัปดาห์; ผู้ลงนามต้องครบตามกฎของบัญชีต้นทางตามยอดนั้น; ลงนามครบ → เกิดรายการ "รอโอน" ที่ `/admin/accounta/funding` (เมนู ACCOUNTA + badge) ฝ่ายการเงินบันทึกวันที่/ยอดจริง/หมายเหตุด้วย PIN หรือระบบจับคู่เองเมื่อพบรายการโอนตรงกันใน statement ทั้งสองบัญชี (ยกเลิกการจับคู่ = คืนเป็นรอโอน)
- **เตือน (ไม่บล็อก)** เมื่อ PR เกินยอดที่โอนเข้าบัญชีนั้นหักยอด PR ที่อนุมัติไปแล้ว (เฉพาะบัญชีที่รับเงินผ่านการโอน)
- ตารางใหม่ `pr_approvals`, `pr_approval_tiers`, `account_approvers`, `fund_transfers`; คอลัมน์ `memos.memo_kind/pay_account_id/from_account_id/to_account_id/week_start`, `purchase_requests.pay_account_id`, `users.is_top_exec`

## รอบถัดไป (ยังไม่ทำ)
- รายงานกระทบยอด PO ↔ เงินโอน ↔ บิลที่ลงบัญชี

## กระทบยอดบัญชีธนาคาร รายเดือน (เจ้าของระบบ 2569-11-26) — หน้า `/admin/accounta/reconcile`
- นำเข้า statement (CSV / Excel จากธนาคาร): อ่านหัวตารางไทย/อังกฤษอัตโนมัติ (ถอน/ฝาก หรือจำนวนเงินช่องเดียวติดลบ/Dr-Cr), ปี พ.ศ./ค.ศ., ลำดับใหม่→เก่าหรือเก่า→ใหม่; มีหน้าตัวอย่างก่อนนำเข้า และเลือกคอลัมน์เองได้
- ตรวจยอดคงเหลือต่อเนื่อง (ยอด = ยอดก่อนหน้า ± รายการ) เพื่อจับ "รายการที่ขาดจากไฟล์"; นำเข้าซ้ำไม่ซ้ำรายการ (hash ต่อรายการ)
- จับคู่อัตโนมัติเฉพาะเมื่อมีตัวเลือกเดียว: จ่าย ↔ รายจ่าย ACCOUNTA (จ่ายแล้ว ยอดเท่ากัน วันห่างไม่เกิน 5 วัน; ถ้ามีหลายใบใช้ชื่อผู้จำหน่ายช่วยตัดสิน), รับ ↔ รายรับ (±3 วัน), โอนระหว่างบัญชีบริษัท (SCB→KBANK ออกกับเข้าตรงกัน ±3 วัน) ที่เหลือคนตัดสิน (จับคู่เอง หรืออธิบายด้วยเหตุผล: ค่าธรรมเนียม, ดอกเบี้ย, ตัดออม, Payroll, ภาษี …)
- ปิดงวดต่อบัญชีต่อเดือน เมื่อทุกรายการจับคู่/อธิบายแล้ว (ยอดไม่ต่อเนื่องต้องใส่เหตุผล); งวดที่ปิดแล้วแก้ไม่ได้ เปิดซ้ำได้เฉพาะเจ้าของระบบ; รายงานพิมพ์ได้
- แสดง "บิลที่บันทึกว่าจ่ายโอน แต่ไม่พบในธนาคาร" ของเดือน
- สิทธิ์: เจ้าของระบบ, ผู้บริหาร (C-level), ผู้มีสิทธิ์ ACCOUNTA · ตารางใหม่ `bank_statements`, `bank_lines`, `bank_recon_periods` + คอลัมน์ `accounta_cash_accounts.purpose`
- สมมติฐาน: ยังไม่เคยเห็นไฟล์ statement จริงของ SCB / KBANK / SME D BANK — ตัวอ่านเขียนแบบยืดหยุ่นและมีหน้าตัวอย่าง/เลือกคอลัมน์เอง
