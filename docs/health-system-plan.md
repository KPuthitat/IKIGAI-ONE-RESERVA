# ระบบสุขภาพพนักงาน (หลายโครงการ) + ผลตรวจสุขภาพ — Integration Plan

> **เฟส 1 (Design) — ยังไม่แตะโค้ด** · รอเจ้าของ "ผ่าน" ก่อนเริ่มเฟส 2
> เป้าหมาย: เปลี่ยนจาก "Mounjaro โครงการเดียว (ฮาร์ดโค้ด)" → **ระบบโครงการ
> สุขภาพหลายโครงการ** ที่มี 3 มุมมอง (ผู้บริหาร/แพทย์/พนักงาน) + รวม **ผลตรวจ
> สุขภาพ** (Pre-employment / Pre-placement / Periodic / Return-to-work)
> เจ้าของเคาะแล้ว (2026-06-05): ร่างแผนก่อน · แพทย์เซนทุกครั้งที่บันทึก/แก้ไข ·
> ผลตรวจ = PDF + ช่องกรอกค่าสำคัญ

---

## 0. หลักการ (อ่านก่อน)
1. **Additive + ไม่ทำข้อมูลหาย** — Mounjaro ปัจจุบันต้องทำงาน 100% ระหว่างทาง;
   ย้ายเข้าเป็น "โครงการแรก" ในระบบใหม่ ไม่รื้อข้อมูลเดิม
2. **ความเป็นส่วนตัวคือหัวใจ** — ข้อมูลสุขภาพดิบเข้าถึงได้แค่ **แพทย์ที่ปรึกษา +
   เจ้าตัว** · ที่เหลือเห็นแค่ภาพรวม · ทุกการเข้าถึง/แก้ไขถูก audit
3. **เทสทุกเฟส** — สคริปต์พิสูจน์ขอบเขตการเข้าถึง (เหมือน test-mounjaro)
   ก่อน deploy ทุกเฟส

---

## 1. โมเดล 3 มุมมอง (เจ้าของกำหนด)

| มุมมอง | เห็นโครงการไหน | ระดับข้อมูล | ทำอะไรได้ |
|---|---|---|---|
| **ผู้บริหาร/HR** (is_hr_analytics) | ทุกโครงการที่มีคนเข้าร่วม ≥1 | ภาพรวม (dashboard) | ดูอย่างเดียว · ไม่เห็นข้อมูลดิบ |
| **แพทย์ที่ปรึกษา** (clinical_role=doctor) | **ทุกโครงการ** (แม้ไม่มีคนเข้าร่วม) | ภาพรวม + ข้อมูลดิบ | สร้าง/ปิดโครงการ · เพิ่ม/ลด/แก้ไขข้อมูล · **เซนด้วยใบประกอบทุกครั้ง** |
| **พนักงาน** | เฉพาะที่ตัวเองเข้าร่วม | ข้อมูลดิบของตัวเอง | กรอกได้เฉพาะช่องติดตามรายวันที่แพทย์เปิดให้ · ไม่เห็นคนอื่น |

> หลักการ 3 ระดับนี้ **มีใน Mounjaro แล้ว** (gateway + license unlock + audit) —
> เฟสถัดไปคือทำให้รองรับ "หลายโครงการ" + เพิ่มการเซนต่อรายการ + ผลตรวจ

---

## 2. โมเดลข้อมูลที่เสนอ (SQLite, idempotent)

### 2.1 Registry โครงการสุขภาพ
```
health_programs   id, key(unique), name, description,
                  kind ('mounjaro' | 'generic' | ...),   -- ใช้เลือก UI/ฟิลด์เฉพาะ
                  active(0/1), allow_self_fields_json,    -- ช่องที่พนักงานกรอกเองได้
                  created_at
```
- seed โครงการแรก: `key='mounjaro'` (kind='mounjaro') — โครงการ Mounjaro เดิม
- แพทย์สร้าง/ปิดโครงการได้จากหน้าจัดการ (เฟส 3)

### 2.2 ผูก enrollment กับโครงการ (generalize ของเดิม)
- เพิ่มคอลัมน์ `program_id` ลง `mounjaro_enrollments` (เปลี่ยนความหมายเป็น
  "health_enrollments") — backfill rows เดิม → program ของ Mounjaro
- `mounjaro_self_logs`, `mounjaro_consent_versions`, `mounjaro_audit_log`
  อ้างถึง enrollment/program (consent ผูกต่อโครงการได้ในอนาคต)
- **คลินิกเฉพาะ Mounjaro** (mounjaro_patients/visits — dose/titration) ยังเป็น
  data ของ kind='mounjaro'; โครงการ kind='generic' ใช้ self-log + วัดค่าทั่วไป
  (ไม่มี titration) — ขยายตารางวัดค่ากลางทีหลังถ้าต้องการ

### 2.3 การเซนของแพทย์ (เจ้าของเลือก: เซนทุกครั้ง)
```
health_signatures   id, actor_id, license_no, action, resource_type,
                    resource_id, program_id, created_at
```
- ทุก write ของแพทย์ (สร้าง/แก้ไข/ลบข้อมูลสุขภาพ) **ต้องส่งเลขใบประกอบมาด้วย** →
  ระบบ verify (เทียบเฉพาะตัวเลข ว.) แล้วบันทึกเป็นลายเซน + audit
- เลิกใช้ session-unlock 8 ชม. สำหรับการ "แก้ไข" (ยังใช้ unlock สำหรับ "เปิดดู"
  ได้) — การบันทึกต้องเซนสด ๆ ทุกครั้ง

### 2.4 ผลตรวจสุขภาพ (เจ้าของเลือก: PDF + ช่องกรอกค่าสำคัญ)
- ต่อยอด `health_checkups` (มี exam_type อยู่แล้ว: pre_employment /
  pre_placement / periodic / return_to_work)
- เพิ่ม: แนบ **PDF เล่มผลตรวจ** (1 ไฟล์/ครั้ง/คน, ≤10MB — nginx รองรับ 12M) +
  **ช่องกรอกค่าสำคัญ** (เช่น น้ำหนัก, BP, FBS, ไขมัน, ผลสรุป/ผ่าน-ไม่ผ่าน)
  เก็บใน JSON หรือคอลัมน์ เพื่อทำกราฟ/แจ้งเตือนค่าผิดปกติ
- **พนักงานเห็นผลตรวจของตัวเอง** · แพทย์เห็นทุกคน · HR/ผู้บริหารเห็นแค่สถานะ
  (ตรวจครบ/ผ่าน) ไม่เห็นไฟล์

---

## 3. กลยุทธ์ migration (กันพัง)
1. seed `health_programs` + โครงการ Mounjaro (kind='mounjaro')
2. เพิ่ม `program_id` ทุกตารางที่เกี่ยว → backfill rows เดิมชี้โครงการ Mounjaro
3. gateway (mounjaro-db) เขียนใหม่ให้ scope ตาม `program_id` + 3 มุมมอง —
   พฤติกรรม Mounjaro เดิมต้องเท่าเดิม (เทสยืนยัน)
4. คงโครงสร้าง/ข้อมูลเดิมไว้ (rollback ได้)

---

## 4. เมนู "สุขภาพพนักงาน" (โครงสร้าง UI)
- **ผลตรวจสุขภาพ** (ทุกคนเห็นของตัวเอง · แพทย์ดู/อัปโหลดได้)
- **โครงการสุขภาพ** (รายการกรองตาม 3 มุมมอง §1)
  - แพทย์: ปุ่ม "สร้างโครงการ" + เข้าไปจัดการผู้ป่วยรายโครงการ (เซนทุกครั้ง)
  - พนักงาน: เห็นเฉพาะที่เข้าร่วม → ลงข้อมูลรายวันที่เปิดให้
  - HR: การ์ดภาพรวมต่อโครงการ (เฉพาะที่มีคน ≥1)

## 5. แผนเฟส
- **เฟส 2:** `health_programs` registry + เพิ่ม `program_id` + backfill Mounjaro
  + gateway scope ตาม program + **เทส** (Mounjaro เดิมเท่าเดิม) — ยังไม่มี UI ใหม่
- **เฟส 3:** เมนู "สุขภาพพนักงาน" + รายการโครงการ 3 มุมมอง + หน้าแพทย์สร้าง/
  จัดการโครงการ
- **เฟส 4:** การเซนของแพทย์ทุก write (verify ใบประกอบ + บันทึกลายเซน + audit)
- **เฟส 5:** แพทย์ตั้งค่าช่องที่พนักงานกรอกเองได้ (ต่อโครงการ)
- **เฟส 6:** ผลตรวจสุขภาพ — อัปโหลด PDF + ช่องกรอกค่าสำคัญ + พนักงานดูของตัวเอง +
  สถานะภาพรวมให้ HR

## 6. ❓ คำถามก่อนเฟส 2
**H1:** โครงการ kind='generic' (ที่ไม่ใช่ Mounjaro) เก็บข้อมูลแบบไหน? เสนอ:
ใช้ self-log + ตารางวัดค่ากลาง (weight/BP/HR/FBS/notes) ไม่มี titration —
โอเคไหม หรือมีตัวอย่างโครงการในใจ (เช่น เลิกบุหรี่, ออกกำลังกาย) ที่ต้องการฟิลด์
เฉพาะ?

**H2:** "แพทย์ที่ปรึกษา" คนเดียวเห็นทุกโครงการ/ทุกคนไข้ หรือยังผูกผู้ป่วยกับ
แพทย์เจ้าของไข้รายคน (เหมือน Mounjaro ตอนนี้)? เสนอ: คงผูกเจ้าของไข้รายคน —
แต่แพทย์ทุกคนเห็น "รายชื่อโครงการ" ได้

**H3:** การเซนทุกครั้ง — ใส่เลข ว. หรือ PIN ก็ได้ หรือต้องเป็นเลข ว. เท่านั้น?
(กระทบ UX: เลข ว. ยาวกว่า PIN)

**H4:** ผลตรวจสุขภาพ "ช่องกรอกค่าสำคัญ" อยากได้ค่าไหนบ้าง (เริ่มต้น)? เสนอ:
น้ำหนัก, ส่วนสูง, BP, FBS, ไขมัน (chol/LDL/HDL/TG), ผลสรุป (ปกติ/ผิดปกติ/ผ่าน-
ไม่ผ่าน) — เพิ่ม/ลดได้
